Read case study
The central idea is a change of coordinates: one vector describes sound samples in time; another describes their frequency components. A readable direct DFT exposes the Fourier-matrix calculation, and a radix-2 FFT computes the same transform efficiently for the hardware visualiser.
One transform, two implementations
The firmware implements both a direct DFT and an iterative radix-2 FFT. Known-signal tests and coefficient comparisons check agreement; an RGB light alone cannot establish that the mathematics is correct. With 128 samples at a nominal 6.4 kHz, bins are 50 Hz apart and Nyquist is 3.2 kHz.
Hardware as a visualiser
An ESP32 reads an analog microphone and maps selected band strengths to a common-cathode RGB LED: 50–250 Hz to red, 300–1000 Hz to green, and 1050–2500 Hz to blue. The physical path is speaker → air → microphone → ESP32; the browser does not inject test samples into the firmware.
Make a frame explainable
The browser's Demo and Presenter views connect tone generation, Web Serial telemetry, and the linear algebra walkthrough. A captured frame keeps samples, Fourier coefficients, and RGB output together so the direct DFT and seven FFT stages can be traced against the same input. A labelled seeded frame supports explanation when the board is unavailable.

Systems & security

    
A localhost-only lab on how early-exit comparisons leak timing, how an attacker can recover a secret from it, and how constant-time comparison closes the leak.

Read case study
Status: learning lab in progress. Comparing secrets byte by byte and returning on the first mismatch leaks how many leading bytes were right through response time. The lab builds the vulnerable comparison, an attacker that measures it, and the constant-time fix. Measured results and the Python-versus-C comparison are WIP.
Scope and safety
The lab runs on localhost against a synthetic secret, and the starter attacker accepts localhost targets only. It must not be used against accounts, credentials, or systems you do not own.
What exists
A Flask login endpoint with vulnerable and fixed modes, an attacker module for measuring and scoring candidates, a check runner, and a C server for a Python-versus-C comparison.
Results
WIP. Raw timing samples, per-position latency distributions, and the vulnerable-versus-constant-time comparison have not been collected yet.

  



    
Conway's Game of Life
maths + hardware

    
Signals & hardware

    
A 32×8 toroidal Game of Life runs on an ESP32 and an LED matrix, streaming entropy and birth/death telemetry to a React dashboard.

    
    
    
Conway's Game of Life · datasheet
Board
32×8, wrapped into a torus
Rule
born with 3 neighbours, survives with 2 or 3

    
ESP32C++MAX7219SSEReact

    
View source on GitHub ↗
View case study ↗

    
Read case study
Each of the eight rows is packed into one 32-bit integer, so neighbor reads, births, deaths, population counts, and state hashes stay compact while the board drives both physical and browser views.
Packed simulation
Eight uint32_t rows represent all 256 cells. Wrapped row and column indices create the torus; bit shifts read neighbors, while popcount computes population, births, and deaths efficiently.
Physical and live outputs
The MD_MAX72XX driver updates four chained FC-16 modules as one 32×8 display. The local HTTP service publishes changed snapshots over one Server-Sent Events stream to the React dashboard.
Session analysis
The firmware ends runs on extinction, repeated-state stagnation, or a generation cap and persists up to 30 summaries. The dashboard charts density, entropy, autocorrelation, peak population, and exports CSV or JSON.

Read case study
Two playable versions share a C++ gameplay core: an ESP32 game with a joystick and OLED, and a pixel-art browser game with PS4 controller or keyboard and mouse controls. The browser version adds a larger world and aimed combat.
ESP32 version
The ESP32 drives a 128×64 OLED, joystick, fire button, and buzzer. Escalating waves add entrance patterns and faster rocks; score chains, multishot, shields, and saved initials make each run more than a survival timer.
Web version
Play in a browser using a PS4 controller or keyboard and mouse. WebAssembly runs the shared C++ gameplay, while Canvas renders a 480×270 pixel-art world. Aiming, a charged laser, manual shields, and precision movement are browser-specific additions.
Practice without changing the leaderboard
The browser adds remappable controls, saved settings, run statistics, and a practice mode that cannot write ranked scores. Browser and ESP32 score tables stay separate, and each platform supplies its own randomness, audio, and storage adapters.

Read case study
An asynchronous analysis system that turns an uploaded rehearsal into separate delivery and voice signals, normalized scores, and focused coaching cards.
Processing boundary
FastAPI handles upload and job orchestration while Celery performs the expensive media work outside the request lifecycle. Railway hosts the deployed backend services, and Redis carries job state between the API and worker.
Signals and scoring
Video analysis derives eye-contact, expression, posture, gesture, movement, and spatial-use signals. The audio path measures pacing, pitch variation, pauses, and filler words before producing normalized delivery scores.
Coaching contract
The coaching layer receives scored telemetry and the chosen speaking archetype. It validates structured LLM output and falls back to deterministic rule-based cards if the provider is unavailable.

Read case study
A caregiver-reviewed media pipeline turns personal photos and videos into approved memories, then presents them through a low-friction feed with narration, recall prompts, cooldowns, and adaptive voice controls.
Review before delivery
Uploads enter Supabase Storage, then a Next.js route asks a locally hosted LLaVA model for summary, people, place, and date context. The resulting memory stays in needs-review state until a caregiver approves it.
Familiarity loop
Approved memories are filtered by cooldown before display. A Like hides an item for 24 hours to reduce repetition; Recall records a meaningful interaction and can surface a later active-recall prompt.
Adaptive access
Repeated missed taps can switch the interface into a larger voice-control mode. A time-based sundowning setting activates a warmer presentation, while ElevenLabs provides generated or familiar-voice narration.

Read case study
cya asks whether an image detector still works after everyday transformations. The retained controlled-RINE model uses intermediate features from a frozen CLIP backbone and a trained linear head; candidate additions were rejected when they failed the robustness gate.
My contribution and the team
I built the repository infrastructure, reproducible configuration, Colab workflows, image-data pipeline, CLIP/RINE baselines, evaluation and robustness tooling, physical-feature experiments, inference backend and CLI, and final-test/submission integration. Rae developed augmentation and the texture candidate; Shan He built initial feature extractors and the React/Vite frontend.
Results with their context
The submission reports a 99.81% mean selection score across three seeds, combining 100.00% clean accuracy with 99.62% mean robustness accuracy. The separate, single-run held-out test reached 99.29% on 141 images. The selection score is not the held-out result or an event ranking.
Scope and limitations
The task covers fully authentic versus fully AI-generated images, not localisation of partial edits. The CLI and FastAPI service share model inference, while React provides the demonstration interface. Outputs are raw, uncalibrated sigmoid scores at T=1; they should not be interpreted as calibrated probabilities or proof of an image's origin.
